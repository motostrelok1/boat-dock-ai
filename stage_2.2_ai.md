# ТЗ: Stage 2.2 — обучение обходу запретных зон

Контекст: Stage 2.1 добавила входы `avoid_dist`/`avoid_angle` (только ближайшая зона), но обучение шло на статичной расстановке зон и без dense-сигнала на приближение к ним. Итог: сеть либо не обучается обходу устойчиво, либо переобучается под конкретную карту.

Ниже — что менять и зачем, по приоритету.

---

## 1. Dense-штраф за приближение к зоне (приоритет №1)

**Почему:** сейчас штраф за зону — это -1000 одноразово, только при столкновении. Всё остальное время зона никак не влияет на score, а курсовой бонус (`+20 * cos(angleDiff)`) действует всегда и тянет нос лодки прямо на зону, если она на линии к цели. Разреженный (sparse) сигнал очень плохо ловится эволюцией — нужен постоянный (dense) градиент.

**Что сделать:**

```js
const safeMargin = 50; // px, подобрать эмпирически
if (avoidDist < safeMargin) {
  const closeness = (safeMargin - avoidDist) / safeMargin; // 0..1
  avoidPenalty = closeness * closeness * AVOID_WEIGHT * dt; // квадрат — резче у самой границы
  score -= avoidPenalty;

  // встречный бонус за уход от зоны
  if (avoidDist > prevAvoidDist) {
    score += (avoidDist - prevAvoidDist) * ESCAPE_WEIGHT;
  }
}
prevAvoidDist = avoidDist;
```

**Важно:** `AVOID_WEIGHT` должен быть подобран так, чтобы вблизи границы штраф перевешивал курсовой бонус (вес 20) — иначе сеть найдёт локальный оптимум «срезать через зону ради курса/времени». Проверять эмпирически: сравнить суммарный reward при «срезать» vs «обойти» на тестовых сценариях.

---

## 2. Рандомизация зон при обучении (приоритет №2)

**Почему:** обучение на фиксированной карте = overfit на конкретный маршрут, а не общий навык. Подтверждается интуицией: на новой случайной карте поведение деградирует.

**Что сделать:**

```js
function randomizeEpisode() {
  const noZones = Math.random() < 0.3; // 30% эпизодов — вообще без зон
  const zoneCount = noZones ? 0 : randInt(1, 15);
  const zones = [];
  for (let i = 0; i < zoneCount; i++) {
    zones.push({
      x: randRange(0, width),
      y: randRange(0, height),
      radius: choice([10, 20, 30]),
    });
  }
  return zones;
}
```

**Обязательно:** держать долю эпизодов без зон (например 30%). Иначе — catastrophic forgetting: сеть, гоняясь за avoid-наградой, теряет базовый навык захода в док.

---

## 3. Curriculum (поэтапное усложнение)

**Почему:** резкий скачок от «нет зон» к «до 15 зон случайно» — слишком сложная задача для эволюции с нуля. Нужен путь от простого к сложному.

**Этапы:**

```
Stage A: 1 маленькая зона (r=10), НЕ на линии лодка→цель       // фон, можно игнорировать
Stage B: 1 зона любого радиуса, специально ставится на линию   // вынуждает реальный манёвр
         лодка→цель
Stage C: 2-3 зоны, образуют "коридор"                          // тест слепой зоны (см. п.4)
Stage D: полный рандом, 0-15 зон, любые радиусы                // финальная генерализация
```

Переход на следующий этап — когда success rate на текущем стабильно > X% (например 80%) на протяжении N поколений.

---

## 4. Расширить видимость сети до 2 ближайших зон (приоритет №3)

**Почему:** сейчас сеть видит только ОДНУ ближайшую зону. Проблемы:
- флиппинг: если две зоны примерно равноудалены, «ближайшая» дёргается между ними от кадра к кадру → дребезг руля;
- слепота к коридорам: лодка «обходит» видимую зону прямо в невидимую вторую.

**Что сделать:** расширить вход 6→10 (по аналогии с миграцией 4→6 из Stage 1→2.1):

```
входы: dist, angle, sin(h), cos(h),
       avoid1_dist, avoid1_angle,   // ближайшая зона
       avoid2_dist, avoid2_angle    // вторая по близости зона (0,0 если нет)
```

```js
nn.migrateInputSize(10); // старые 6 колонок копируются, новые 4 — нули
```

Сеть: `NeuralNetwork(10, 12, 1)` — увеличить скрытый слой вместе с входом (было 8, сейчас входов больше — ёмкости должно хватать на более сложную подзадачу).

**Дешёвая альтернатива**, если не готовы расширять вход: выбирать «ближайшую» зону не по евклидову расстоянию, а по time-to-impact с учётом текущего курса — снижает дребезг, но не решает проблему коридоров.

---

## 5. Сглаживание управления (опционально, низкий приоритет)

**Почему:** сеть безpамятная (чистый feedforward), не знает свой предыдущий руль → возможен jitter, особенно у границы зоны.

```
вход №11: prevRudder // значение руля с прошлого кадра
```

Штраф за резкое изменение руля (доп. к существующему `-|rudder|*dt*2`):

```js
score -= Math.abs(rudder - prevRudder) * dt * SMOOTH_WEIGHT;
```

---

## 6. Дообучение, а не обучение с нуля

**Почему:** есть уже рабочий мозг, хорошо заходящий в док без зон. Переоткрывать этот навык заново — трата времени эволюции.

**Что сделать:**
1. Взять чекпоинт «чистого» докинга (без зон).
2. `migrateInputSize(10)` — новые колонки нулями.
3. Дообучать (мутация+кроссовер) уже по curriculum из п.3, начиная с Stage A.

---

## 7. Метрики отбора

Сейчас один суммарный `score`. Риск: сеть с частыми столкновениями, но быстрым докингом, может обгонять по score аккуратную сеть — если бонус за скорость (`+(maxTime-time)*100`) перевешивает штраф за зону.

**Рекомендация:** логировать отдельно при отборе элиты:
- `dockSuccessRate` — % успешных докингов;
- `collisionRate` — % эпизодов со столкновением с avoid-зоной.

При равном/близком score предпочитать особь с меньшим `collisionRate`. Можно ввести мягкий tie-breaker в фитнес-функции турнирного отбора.
